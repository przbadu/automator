  <action>
Create `backend/app/services/kb_agent_tools.py` with:

1. **Tool definitions in OpenAI format** (`_KB_TOOLS_OPENAI` list): Define 7 tools:
   - `kb_ls`: List files/subfolders at a path. Params: `path` (string, default "/")
   - `kb_tree`: Get hierarchical KB structure. Params: `path` (string, default "/"), `depth` (int, default 2), `limit` (int, default 50)
   - `kb_grep`: Regex search document contents. Params: `pattern` (string, required), `path` (string, optional folder scope), `case_insensitive` (bool, default false)
   - `kb_glob`: Match documents by filename pattern. Params: `pattern` (string, required)
   - `kb_read`: Read document content. Params: `path` (string, required), `offset` (int, optional line offset), `limit` (int, optional line limit)
   - `kb_semantic_search`: Semantic similarity search across all documents. Params: `query` (string, required), `top_k` (int, default 5)
   - `analyze_document`: Delegate deep analysis of a specific document to the document analysis sub-agent. Params: `document_id` (string, required), `question` (string, required). Description should say "Use when you've identified a specific document that needs thorough reading and analysis."

2. **Tool definitions in Anthropic format** (`_KB_TOOLS_ANTHROPIC` list): Same 7 tools using `input_schema` instead of `parameters`, and `name`/`description` at top level (not nested under `function`). Follow exact pattern from `_DOCUMENT_TOOLS_ANTHROPIC` in sub_agent_tools.py.

3. **Executor wrapper functions** -- each decorated with `@observe()` from langfuse, each calls the Phase 3 service and formats the Pydantic result model into a plain string for the LLM:
   - `async def execute_kb_ls(path, user_id, db)` -> calls `kb_tools_service.kb_ls()`, formats LsResult as text showing folders (with trailing /) and files with sizes
   - `async def execute_kb_tree(path, depth, limit, user_id, db)` -> calls `kb_tools_service.kb_tree()`, formats TreeResult as indented text tree. Use 2-space indent per depth level. Show truncation warning if `result.truncated`.
   - `async def execute_kb_grep(pattern, path, case_insensitive, user_id, db)` -> calls `kb_tools_service.kb_grep()`, formats as "filename:line_number: text" lines grouped by document. **Limit max_matches=10** for agent context efficiency (stricter than the raw tool's 50).
   - `async def execute_kb_glob(pattern, user_id, db)` -> calls `kb_tools_service.kb_glob()`, formats as list of matching paths
   - `async def execute_kb_read(path, offset, limit, user_id, db)` -> calls `kb_tools_service.kb_read()`, returns content directly. **Default limit=100 lines** when offset is provided but limit is not (prevents massive output).
   - `async def execute_kb_semantic_search(query, top_k, user_id)` -> uses ChromaDB collection directly (same pattern as `search_within_document` in sub_agent_tools.py but WITHOUT document_id filter -- searches across ALL user documents). Format results as "filename (chunk N, relevance: score): content_preview".

   Each executor should call `get_client().update_current_span(metadata={...})` with relevant params and result counts.

   For error results (where the Pydantic model has an `error` field set), return the error message as a friendly string that guides the LLM (e.g., "Folder '/reports/2024' not found. Use kb_tree to explore available folders.").

4. **Add to config.py**: Add `explorer_max_iterations: int = 8` to the Settings class (after `sub_agent_max_iterations`).

Do NOT implement `analyze_document` executor here -- that requires the sub-agent service and will be done in Plan 02. Just define the tool definition dicts.
