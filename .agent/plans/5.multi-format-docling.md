# Module 5: Multi-Format Document Support via Docling

## Context

The app currently only supports `.txt` and `.md` uploads (plain UTF-8 read). Module 5 adds PDF, DOCX, PPTX, HTML, XLSX, and CSV support using **Docling** as the document converter. Docling converts any supported format to markdown text, which feeds directly into the existing chunking pipeline. No changes to chunking, embedding, or retrieval logic needed.

**Complexity:** ⚠️ Medium — touches backend services, router, DB migration, frontend, and tests, but each change is straightforward.

### Task 2: Database migration — add "converting" status

**File:** `backend/migrations/005_add_converting_status.sql`

The current CHECK constraint on `documents.status` (migration 002) doesn't include `converting`. SQLite doesn't support `ALTER TABLE ... DROP CONSTRAINT`, so we need to recreate the table:

```sql
-- Add 'converting' to the status CHECK constraint
ALTER TABLE documents RENAME TO documents_old;

CREATE TABLE documents (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    filename TEXT NOT NULL,
    file_size INTEGER NOT NULL,
    mime_type TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending', 'processing', 'converting', 'chunking', 'extracting_metadata', 'embedding', 'completed', 'failed')),
    chunk_count INTEGER NOT NULL DEFAULT 0,
    error_message TEXT,
    content_hash TEXT,
    metadata TEXT DEFAULT '{}',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

INSERT INTO documents SELECT * FROM documents_old;
DROP TABLE documents_old;

CREATE INDEX IF NOT EXISTS idx_documents_user_id ON documents(user_id);
CREATE INDEX IF NOT EXISTS idx_documents_status ON documents(status);
CREATE INDEX IF NOT EXISTS idx_documents_user_content_hash ON documents(user_id, content_hash);
CREATE INDEX IF NOT EXISTS idx_documents_user_filename ON documents(user_id, filename);
```

Also update `backend/app/database.py` to run this migration at startup (follow existing pattern for migrations 001-004).

**Validation:** Start backend, verify migration runs without error. Insert a row with `status='converting'` — should succeed.

### Task 3: Create conversion service

**New file:** `backend/app/services/conversion_service.py`

```python
DOCLING_EXTENSIONS = {".pdf", ".docx", ".pptx", ".html", ".htm", ".xlsx", ".csv"}
PLAINTEXT_EXTENSIONS = {".txt", ".md"}
ALL_SUPPORTED_EXTENSIONS = DOCLING_EXTENSIONS | PLAINTEXT_EXTENSIONS
```

**Functions:**
- `needs_conversion(filename: str) -> bool` — True if extension in `DOCLING_EXTENSIONS`
- `convert_document(file_path: Path) -> str` — Instantiate `DocumentConverter()`, call `converter.convert(source=str(file_path))`, return `result.document.export_to_markdown()`. This is synchronous (Docling is sync).

**Validation:** Manual test with a small PDF file.

### Task 6: Update ingestion service — add converting step

**File:** `backend/app/services/ingestion_service.py`

Modify `ingest_document()`:
1. After "processing" status, check `needs_conversion(filename)`
2. If yes: set status to `"converting"`, run `convert_document(file_path)` via `asyncio.get_event_loop().run_in_executor(None, ...)`
3. If no: use existing `read_file_text()` fast path
4. Rest of pipeline (chunking, metadata, embedding, store) unchanged

Also update `reset_stuck_documents()` to include `'converting'` in the stuck states WHERE clause.

**Validation:** Upload PDF → observe SSE status: pending → processing → converting → chunking → extracting_metadata → embedding → completed. Upload .txt → skips "converting".
