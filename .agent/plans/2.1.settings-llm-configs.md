# Module 2 Extended: Settings Page with LLM Configurations & Documents

## Complexity: ⚠️ Medium

## Context

The app currently has a top nav bar with Chat/Documents tabs, and LLM configuration lives entirely in `.env` (single global config). The user wants to:
1. Remove the tab bar — Chat becomes the sole main view
2. Add a Settings page (gear icon in sidebar) with two tabs:
   - **LLM Configurations** — user-managed, per-user, multiple configs with one default
   - **Documents** — relocated from the main nav
3. Replace `.env`-based LLM config with user-managed configs stored in the DB

This means chat must dynamically use the user's default LLM config rather than server-wide env vars.

---

## Design Decisions

- **Provider-native SDKs** — Use the OpenAI SDK for openai/gemini/grok/openrouter/openai_compatible providers (they all support OpenAI-compatible endpoints). Use the Anthropic SDK natively for the `anthropic` provider (don't fight the framework).
- **Provider → base URL mapping** is a server-side constant. Only `openai_compatible` requires user-supplied `api_url`.
- **API keys encrypted at rest** — Use Fernet symmetric encryption (`cryptography` library). Encryption key stored in `.env` as `ENCRYPTION_KEY`. Auto-generated on first backend startup if not set (written to `.env`). Keys encrypted before DB insert, decrypted only when creating the LLM client.
- **Default enforcement** — exactly one config per user can be `is_default=1`. First config auto-becomes default.
- **Env var fallback** — if user has no DB configs but `.env` has LLM keys, those still work. Graceful migration path.
- **Embedding config stays in `.env`** — server-side concern, not user-facing.
- **Settings access** — gear icon in ChatLayout sidebar footer. Full-screen settings with back-to-chat button.

### Provider Details

| Provider | SDK | Base URL |
|----------|-----|----------|
| `openai` | OpenAI | `https://api.openai.com/v1` |
| `gemini` | OpenAI | `https://generativelanguage.googleapis.com/v1beta/openai` |
| `grok` | OpenAI | `https://api.x.ai/v1` |
| `openrouter` | OpenAI | `https://openrouter.ai/api/v1` |
| `openai_compatible` | OpenAI | User-provided `api_url` |
| `anthropic` | Anthropic | `https://api.anthropic.com` (native SDK, no base_url needed) |

## Implementation Tasks

### Task 1: Database Migration

**New file:** `backend/migrations/003_llm_configs_schema.sql`

```sql
CREATE TABLE IF NOT EXISTS llm_configs (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    provider TEXT NOT NULL CHECK (provider IN ('openai_compatible','openai','gemini','anthropic','grok','openrouter')),
    api_key_encrypted TEXT NOT NULL,
    api_url TEXT,
    model_name TEXT NOT NULL,
    is_default INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_llm_configs_user_id ON llm_configs(user_id);
```

Note: Column is `api_key_encrypted` to make it explicit that the value is Fernet-encrypted.

### Task 2: Backend — Encryption Service

**New file:** `backend/app/services/encryption_service.py`

- Uses `cryptography.fernet.Fernet` for symmetric encryption
- Reads `ENCRYPTION_KEY` from settings/env
- If not set, auto-generates a key and appends it to `.env` file
- Exports: `encrypt_value(plaintext: str) -> str` and `decrypt_value(ciphertext: str) -> str`
- Fernet tokens are URL-safe base64 strings, safe to store in SQLite TEXT column

**Add to requirements.txt:** `cryptography`

**Add to `backend/app/config.py`:** `encryption_key: str = ""` field

### Task 3: Backend — Pydantic Models

**New file:** `backend/app/models/llm_config.py`

### Task 4: Backend — LLM Configs CRUD Router

**New file:** `backend/app/routers/llm_configs.py`

Prefix: `/llm-configs`

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/llm-configs` | GET | List user's configs (masked keys) |
| `/llm-configs` | POST | Create config. Encrypt api_key. Resolve api_url from provider map. First config → auto-default. |
| `/llm-configs/{id}` | PUT | Update config. Re-encrypt api_key if changed. Re-resolve api_url if provider changes. Handle default toggling. |
| `/llm-configs/{id}` | DELETE | Delete config. Promote next most recent if deleting default. |
| `/llm-configs/default` | GET | Get user's default config (or 404) |

**Default enforcement logic:**
- Setting `is_default=true` → unset all others first (in same transaction)
- Cannot unset default if it's the only config (must always have one default when configs exist)
- Deleting default → promote most recently created remaining config

**Key encryption flow:**
- On create/update: `encrypt_value(api_key)` → store as `api_key_encrypted`
- On read for response: `decrypt_value(api_key_encrypted)` → `mask_api_key()` → `api_key_masked`
- On read for LLM client: `decrypt_value(api_key_encrypted)` → use raw key

**Register in:** `backend/app/main.py`

**Validate:** curl CRUD operations, verify masked keys, verify DB contains encrypted (not plaintext) keys.

**Modify:** `backend/app/routers/chat.py` (`send_message` endpoint)
