# Module 6.1: Langfuse Retrieval Pipeline Observability

⚠️ **Medium** — Touches langfuse service, all retrieval pipeline services, embedding service, and chat router. Well-scoped, single-pass feasible.

## Context

### Problem
Langfuse currently only traces LLM chat completions (via the auto-wrapped `langfuse.openai.AsyncOpenAI` client). The entire retrieval pipeline — embeddings, vector search, BM25 keyword search, RRF fusion, and cross-encoder reranking — is **completely invisible** in Langfuse. Traces show "undefined" for tool_calls, role, etc. because Langfuse only captures raw OpenAI completion fields with no structured retrieval metadata.

### What's Traced Now
- Chat completions (auto-wrapped via `langfuse.openai.AsyncOpenAI`)
- Title generation (same wrapped client)
- Metadata extraction (OpenAI path only, Anthropic invisible)

### What's NOT Traced (and should be)
- Embedding API calls (uses raw `openai.AsyncOpenAI`, not wrapped)
- Vector search (ChromaDB query) — latency, result count, distances
- BM25 keyword search — cache hit/miss, result count, scores
- RRF fusion — input counts, output count, score distribution
- Reranker — API call latency, score distribution, model used
- Full retrieval pipeline — end-to-end timing, which steps ran, config used

### Goal
Add Langfuse `@observe()` decorator tracing to every retrieval pipeline step so that each chat request produces a complete trace showing: query → embedding → vector search → (keyword search → fusion) → (reranking) → final results, with all intermediate metrics visible.

## Key Design Decisions

1. **`@observe()` decorators over manual spans** — Langfuse's decorator approach automatically creates nested parent-child spans. No manual span management needed. Each decorated function becomes a child of its caller.

2. **Metadata over input/output** — We use `update_current_observation(metadata={...})` to attach structured metrics rather than logging full inputs/outputs (which could be large embedding vectors or chunk texts). Keeps traces lightweight.

3. **Embedding client wrapped** — The embedding service currently uses raw `openai.AsyncOpenAI`. Switching to the Langfuse-wrapped client means embedding API calls get auto-traced with model, tokens, and latency — zero additional code.

4. **Debug endpoint** — A simple config dump endpoint lets you verify the setup without needing to trigger a chat message. Useful for quick sanity checks: "is the reranker configured? what embedding dimensions are set?"

5. **No auth on debug endpoint** — This is a local-only app. The endpoint returns config, not secrets (no API keys exposed).
