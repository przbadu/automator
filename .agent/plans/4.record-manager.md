# Module 3: Record Manager

## Context

Currently, re-uploading the same file creates a duplicate document with a separate set of ChromaDB chunks. There is no deduplication — if a user uploads the same file 5 times, they get 5 documents and 5x the chunks. The Record Manager adds content hashing (SHA-256) and change detection so that:

- Identical content is never processed twice (skip)
- Same filename with different content triggers an update (delete old chunks, re-ingest)
- All deduplication is user-scoped

**Complexity: ⚠️ Medium** — touches backend migration, upload endpoint, ingestion service, models, frontend hook/components, and tests. Well-scoped and single-pass feasible.

## Task 1: Database Migration — Add `content_hash` Column

**File:** `backend/app/database.py` (modify `init_db()`)

SQLite doesn't support `ALTER TABLE ADD COLUMN IF NOT EXISTS`, so add a Python migration step after SQL file execution:

```python
# After the sql_files loop in init_db():
try:
    await db.execute("ALTER TABLE documents ADD COLUMN content_hash TEXT")
except Exception:
    pass  # Column already exists
await db.execute("CREATE INDEX IF NOT EXISTS idx_documents_user_content_hash ON documents(user_id, content_hash)")
await db.execute("CREATE INDEX IF NOT EXISTS idx_documents_user_filename ON documents(user_id, filename)")
await db.commit()
```

**Validation:** Start backend, verify `content_hash` column exists. Restart — no errors (idempotent).

## Task 2: Record Manager Service

**New file:** `backend/app/services/record_manager.py`

Two functions:

1. **`compute_content_hash(content: bytes) -> str`** — SHA-256 hex digest
2. **`check_duplicate(db, user_id, content_hash, filename) -> dict | None`** — returns action recommendation:

| Same hash? | Same filename? | Action | Behavior |
|------------|---------------|--------|----------|
| Yes | Yes or No | `skip` | Return existing doc, don't re-process |
| No | Yes | `update` | Re-use existing doc ID, delete old chunks, re-ingest |
| No | No | `None` | New document, proceed normally |

Edge case: if existing doc with same filename has status in `('processing', 'chunking', 'embedding')`, return `action="conflict"` — the caller should return HTTP 409.

**Validation:** Import and call `compute_content_hash(b"test")` — returns deterministic 64-char hex string.

## Task 4: Modify Upload Endpoint for Deduplication

**File:** `backend/app/routers/documents.py`

After reading file content (line 50) and before saving:

1. `content_hash = compute_content_hash(content)`
2. `result = await check_duplicate(db, user_id, content_hash, filename)`
3. Branch on result:

**`action="skip"`:**
- Return HTTP 200 with existing doc + `duplicate=True`
- Publish SSE: `{"type": "status_update", "document_id": ..., "status": "skipped", "progress": "Duplicate content — skipped"}`
- Don't save file, don't create record

**`action="update"`:**
- Delete old ChromaDB chunks (`collection.delete(where={"document_id": existing_id})`)
- Delete old file from disk
- Save new file using existing doc_id
- Update DB record: set `content_hash`, `file_size`, `mime_type`, `status='pending'`, `chunk_count=0`, `updated_at`
- Queue background ingestion with existing doc_id
- Return HTTP 200 with updated doc + `updated=True`

**`action="conflict"`:**
- Return HTTP 409: "Document is currently being processed"

**`None` (new doc):**
- Current flow + store `content_hash` in INSERT

Also update the `status_code` on the route decorator: change from `status_code=201` to using `Response` to set status dynamically (200 vs 201).

**Validation:**
- Upload new file → 201, `content_hash` populated
- Upload same file again → 200, `duplicate: true`
- Upload same filename, different content → 200, `updated: true`
- Upload while previous ingestion is running → 409

## Task 5: Update Ingestion Service — Clean Old Chunks

**File:** `backend/app/services/ingestion_service.py`

Before the ChromaDB upsert (line 94), add:
```python
# Remove any existing chunks for this document (handles re-ingestion on update)
try:
    collection.delete(where={"document_id": doc_id})
except Exception:
    pass
```

This is idempotent — no-op for new documents, cleans up for updated documents.
