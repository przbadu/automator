# Module 8: Sub-Agents

## Complexity: 🔴 Complex
Introduces intent classification, tool-calling loop, new SSE events, and a new frontend component. Execute tasks sequentially with validation gates.

## Context
The RAG app currently uses a linear pipeline: query → contextualize → retrieve chunks → LLM completion. This works well for focused questions, but falls short when users need comprehensive document analysis (e.g., "summarize this entire document", "extract all key findings from report.pdf"). Module 8 adds a **sub-agent** that can autonomously read, search, and analyze a full document using a tool-calling loop, then synthesize a comprehensive answer.

---

## Architecture

**Flow with sub-agent:**
```
User message
  → Intent classification (cheap LLM call: "does this need full-doc analysis?")
  → YES: Sub-agent loop (tool calls: read chunks, search within doc, get metadata → repeat → final answer)
  → NO: Normal RAG pipeline (existing flow, unchanged)
```

**Key design decisions:**
1. **LLM-based intent classification** — heuristics are too unreliable ("summarize" could mean many things). A lightweight LLM call with the user's document list provides accurate routing.
2. **Pre-routing, not nested delegation** — the intent classifier runs *before* the main LLM, not as a tool the main LLM calls. This avoids nested tool-calling complexity and works even without tool-calling support.
3. **Graceful fallback** — if the LLM provider doesn't support tool calling, fall back to injecting all document chunks into context for a single-shot completion.
4. **Kill switch** — `SUB_AGENT_ENABLED=false` bypasses everything.

### Task 2: Sub-Agent Tool Definitions
**New file:** `backend/app/services/sub_agent_tools.py`

Define 3 tools in OpenAI function-calling format + async executor functions:

1. **`read_document_chunks`** — Read all/range of chunks from ChromaDB for a document.
   - Params: `document_id`, `start_chunk` (default 0), `max_chunks` (default from config)
   - Query ChromaDB with `where={"document_id": doc_id}`, sort by `chunk_index`

2. **`search_within_document`** — Semantic search within a single document.
   - Params: `document_id`, `query`, `top_k` (default 5)
   - Embed query, ChromaDB query with `where={"$and": [{"document_id": doc_id}, {"user_id": uid}]}`

3. **`get_document_info`** — Get document metadata and stats.
   - Params: `document_id`
   - SQLite query on documents table

All executors take `user_id` (not exposed to LLM) for data isolation. Each decorated with `@observe()`.

**Reuse:** `embedding_service.py:generate_embeddings()` for query embedding, ChromaDB client from `retrieval_service.py` patterns.

**Validate:** Unit-test each tool function with a known ingested document.

### Task 4: Sub-Agent Service (Tool-Calling Loop)
**New file:** `backend/app/services/sub_agent_service.py`

```python
@observe(name="sub_agent_execution")
async def run_sub_agent(
    user_message, document_id, document_filename,
    user_id, chat_history, client, model, provider,
    stop_event, db
) -> AsyncGenerator[dict, None]:
```

Yields SSE event dicts with these types:
- `sub_agent_start` — `{type, document}`
- `sub_agent_tool_call` — `{type, tool, args}`
- `sub_agent_tool_result` — `{type, tool, summary}`
- `delta` — `{type, content}` (final streamed response)
- `sub_agent_end` — `{type}`

**OpenAI tool-calling loop:**
1. System prompt: "You are analyzing '{filename}'. Use tools to read/search the document, then answer."
2. Messages: system + recent history + user message
3. `client.chat.completions.create(tools=TOOL_DEFS, stream=False)` — non-streaming for tool rounds
4. If `tool_calls` in response → yield events, execute tools, append results, loop (max `sub_agent_max_iterations`)
5. Final response (no tool calls) → re-issue with `stream=True`, yield `delta` events
6. Yield `sub_agent_end`

**Anthropic path:** Use `client.messages.create(tools=...)` with Anthropic tool format. Parse `tool_use`/`tool_result` content blocks.

**Fallback (no tool support):** Catch error on first tool call → read ALL chunks of target document → inject into system prompt → standard streaming completion.

**Validate:** Upload a document, call `run_sub_agent()` → yields `sub_agent_start`, tool call events, `delta` events, `sub_agent_end`.

### Task 5: Integrate Sub-Agent into Chat Router
**File:** `backend/app/routers/chat.py`

Modify `send_message()`:

1. **After query contextualization, before retrieval** — add intent classification:
   ```python
   if settings.sub_agent_enabled:
       doc_cursor = await db.execute(
           "SELECT id, filename, chunk_count FROM documents WHERE user_id = ? AND status = 'completed'",
           (current_user["id"],),
       )
       user_documents = [{"id": r[0], "filename": r[1], "chunk_count": r[2]} for r in await doc_cursor.fetchall()]
       intent = await classify_intent(user_message=req.content, user_documents=user_documents, ...)
   ```

2. **Branch `event_generator`:**
   - If `intent.needs_sub_agent` → use `run_sub_agent()` to generate events
   - Otherwise → existing retrieval + `stream_chat_completion()` pipeline (unchanged)

3. **Save metadata:** `{"sub_agent": true, "target_document": filename, "sources": [...]}` on the assistant message.

**Validate:** Upload doc → "Summarize this document" → SSE stream contains `sub_agent_start`/`sub_agent_end`. Ask "What is 2+2?" → normal flow, no sub-agent events.
