## Database Schema

### `threads`
| Column | Type | Notes |
|--------|------|-------|
| id | uuid | PK, gen_random_uuid() |
| user_id | uuid | FK auth.users, NOT NULL |
| title | text | DEFAULT 'New Chat' |
| openai_response_id | text | nullable, dropped in Module 2 |
| created_at | timestamptz | DEFAULT now() |
| updated_at | timestamptz | DEFAULT now(), auto-trigger |

### `messages`
| Column | Type | Notes |
|--------|------|-------|
| id | uuid | PK, gen_random_uuid() |
| thread_id | uuid | FK threads(id) ON DELETE CASCADE |
| user_id | uuid | FK auth.users, NOT NULL |
| role | text | CHECK ('user', 'assistant') |
| content | text | NOT NULL |
| metadata | jsonb | DEFAULT '{}', for citations |
| created_at | timestamptz | DEFAULT now() |

**RLS on both tables:** SELECT/INSERT/UPDATE/DELETE where `auth.uid() = user_id`.
**Indexes:** `user_id` on threads, `thread_id` + `user_id` on messages.

**Module 2 transition note:** `openai_response_id` is the only OpenAI-specific column. Messages use a generic schema (role + content + metadata) reusable with any provider.

### Task 6: OpenAI Compitable Responses API + SSE Streaming
**Files:** `services/openai_service.py`, `routers/chat.py`, `models/chat.py`

**Pydantic models:** `CreateThreadRequest`, `SendMessageRequest`, `ThreadResponse`, `MessageResponse`

**Endpoints:**
- `POST /threads` — create thread
- `GET /threads` — list user's threads
- `GET /threads/{id}` — get thread
- `DELETE /threads/{id}` — delete thread + cascade
- `GET /threads/{id}/messages` — list messages
- `POST /threads/{id}/messages` — send message, stream response via SSE

**OpenAI service core:**
1. Call `openai_client.responses.create(stream=True, model="gpt-4.1", input=message, previous_response_id=...)`
2. Iterate streaming events, yield deltas
3. On completion, capture response ID + full text

**SSE format:**
- `data: {"type": "delta", "content": "..."}` — streaming tokens
- `data: {"type": "done", "message_id": "..."}` — completion

**After streaming:** Save assistant message to DB, update thread's `openai_response_id`.

**Validate:** Send message via curl, verify SSE stream, check messages in DB, send follow-up (proves thread continuity via `previous_response_id`).

### Task 7: Chat UI
RESPECT /frontend-design skills for building beautiful chat interface

**Files:** `lib/api.ts`, `hooks/useChat.ts`, `hooks/useSSE.ts`, all chat components

**api.ts:** Fetch wrapper attaching Supabase session token as Bearer auth.

**useSSE.ts:** Uses `fetch` + `ReadableStream` (not EventSource, since we need POST + auth headers). Parses SSE lines, calls delta callback.

**useChat.ts:** State for threads, current thread, messages, streaming status. CRUD operations.

**Layout:**
- Left sidebar: thread list + "New Chat" button
- Main area: scrollable messages + fixed input at bottom
- User messages right-aligned, assistant left-aligned
- Streaming: partial text displayed as deltas arrive

**Validate:** Create thread, send message, see streaming response, send follow-up (context preserved), switch threads, delete thread, refresh (persists).
