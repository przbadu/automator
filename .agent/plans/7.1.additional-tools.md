# Module 7.1: Additional Tools (Text-to-SQL + Web Search)

⚠️ **Medium** — Extends existing sub-agent tool system with 2 new tools. Touches tool definitions, intent classifier, sub-agent service, chat router, frontend, and tests.

## Context

The PRD's Module 7 specified "Additional Tools" — Text-to-SQL and web search fallback. This was skipped in favor of citations (now labeled Module 7). The sub-agent system (Module 8) provides the tool-calling infrastructure. This module adds the two missing tools on top of it.

**Problem:** The sub-agent currently only has document-analysis tools. Users can't query their own data ("how many documents do I have?") or get answers when documents don't cover the topic ("what's the latest news on X?").

**Solution:** Add `query_database` and `web_search` tools to the sub-agent, generalize it to work without a target document, and expand intent classification to route to these tools.

---

## Core Design Decision

**Generalize the sub-agent into a tool-using agent** rather than creating separate pipelines.

- The sub-agent's tool-calling loop already handles arbitrary tools — we just add new ones
- Intent classifier gains new routing categories (SQL, web search) that trigger the sub-agent
- `run_sub_agent()` becomes usable without a `document_id` (optional param)
- When no document is targeted, use a generic "assistant with tools" system prompt
- All tools (document + SQL + web) are available simultaneously — the LLM picks what it needs

## Task 2: Text-to-SQL Tool

**New file:** `backend/app/services/sql_tool.py`

### Schema Description

`get_user_schema() -> str` — Returns a static description of user-visible tables:

```
Tables available (all filtered by your user_id):

documents: id, filename, file_size, mime_type, status, chunk_count, error_message, created_at, updated_at, metadata
threads: id, title, created_at, updated_at
messages: id, thread_id, role, content, metadata, created_at
```

### SQL Validation

`validate_sql(query: str) -> tuple[bool, str]`:
- Strip and uppercase for checking
- Must start with `SELECT` (after stripping whitespace/comments)
- Reject if contains: `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE`, `ATTACH`, `DETACH`, `PRAGMA`, `GRANT`, `REVOKE`, `;` (multi-statement)
- Reject if no `user_id` reference found (must contain `user_id`)
- Return `(True, "")` or `(False, "reason")`

### Query Execution

`execute_sql_query(sql_query: str, user_id: str, db: aiosqlite.Connection) -> str`:
1. Call `validate_sql()` — return error string if invalid
2. Replace literal `'{USER_ID}'` with `?` parameter binding
3. Execute with `asyncio.wait_for(timeout=settings.text_to_sql_timeout_seconds)`
4. Fetch up to `settings.text_to_sql_max_rows` rows
5. Format as readable text table (column headers + rows)
6. Decorate with `@observe(name="tool_execute_sql")`
7. Log metadata: query, row_count, execution_time

### Tool Definition (OpenAI format)

```python
{
    "type": "function",
    "function": {
        "name": "query_database",
        "description": "Execute a read-only SQL query against the user's data. Tables: documents (id, filename, file_size, mime_type, status, chunk_count, created_at, updated_at, metadata), threads (id, title, created_at, updated_at), messages (id, thread_id, role, content, created_at). All queries MUST include WHERE user_id = '{USER_ID}'. Only SELECT queries allowed.",
        "parameters": {
            "type": "object",
            "properties": {
                "sql_query": {
                    "type": "string",
                    "description": "SELECT query with user_id = '{USER_ID}' filter"
                }
            },
            "required": ["sql_query"]
        }
    }
}
```

Plus equivalent Anthropic format.

**Validation:** Call with `SELECT COUNT(*) FROM documents WHERE user_id = '{USER_ID}'` → returns row count. Call with `DROP TABLE documents` → returns error.

## Task 3: Web Search Tool

**New file:** `backend/app/services/web_search_tool.py`

Uses `httpx.AsyncClient` (already a dependency).

### Provider Implementations

`search_web(query: str, max_results: int | None = None) -> str`:
- Dispatches to configured provider
- Decorated with `@observe(name="tool_web_search")`

**SearXNG** (default, self-hosted):
```python
GET {web_search_url}/search?q={query}&format=json&categories=general
```
Parse `results[].title`, `results[].url`, `results[].content`.

**Tavily:**
```python
POST https://api.tavily.com/search
Body: {"query": query, "max_results": N, "api_key": key}
```

**Brave:**
```python
GET https://api.search.brave.com/res/v1/web/search?q={query}&count=N
Header: X-Subscription-Token: {key}
```

### Result Formatting

```
Web Search Results for "{query}":

1. {title}
   {url}
   {snippet}

2. {title}
   ...
```

On error → return descriptive error string (LLM handles gracefully).

**Validation:** With SearXNG configured, `search_web("python asyncio")` returns formatted results. Without config, returns error message.

## Safety Considerations (Text-to-SQL)

1. **SELECT-only**: Reject all non-SELECT statements at string level
2. **User-scoped**: Every query must reference `user_id`; bind as parameterized `?`
3. **Row limit**: Hard cap at `text_to_sql_max_rows` (default 50)
4. **Timeout**: `asyncio.wait_for()` with configurable seconds (default 5)
5. **No multi-statement**: Reject queries containing `;`
6. **No schema mutation**: Reject DDL keywords (ALTER, CREATE, DROP, ATTACH, PRAGMA)
